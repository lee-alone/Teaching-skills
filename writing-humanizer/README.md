# Writing Humanizer (Non-Fiction & Technical Edition)

专注于**技术文章、教学指南、知识科普与深度评论**的去 AI 味与结构去模板化工具。

---

## 💡 为什么需要这个项目？

当前市面上的“去 AI 味”工具大多停留在机械替换几个敏感词、盲目拆碎长句子，甚至粗暴添加口语俚语。对于**技术、教学与知识类文章**而言，这种做法不仅无法去除 AI 感，反而严重破坏了文章的严肃性与专业度。

本项目立足于对**大语言模型（LLM/RLHF）生成文本与人类专业写作结构差异**的学术研究成果（涵盖 OpenAI 对齐研究、计算文体学与语篇分析），直击 AI 表述的四大核心病灶：

1. **RLHF 长度与充水偏见**：模型为了讨好奖励模型，通篇充斥“我们需要明确的是”、“值得一提的是”等无营养**元话语（Metadiscourse）**，并在结尾强行进行“开启了数字化全新范式”等**假大空升华**。
2. **论证均质八股化**：段落结构高度对称，机械循环“观点 $\rightarrow$ 阐述 $\rightarrow$ 总结”，滥用“首先、其次、综上所述”等连接词，掩盖了逻辑内部的因果递进。
3. **动词弱化与名物化堆叠**：频繁使用“进行优化”、“实现...的提升”等弱动词空转；教学文章容易写成无机制解释的“监控摄像头式操作流水账”。
4. **虚假深刻的“翻案腔”**：无靶自立，滥用“不是……而是……”、“不仅是……更是……”等虚假对立句式。

---

## 🎯 核心原则

- **信息守恒（零幻觉）**：绝不凭空补充未经说明的技术细节、代码参数或虚假案例；绝不删减任何技术限制条件与安全警告。
- **技术实体绝对保护**：代码块、命令、配置参数、文件路径、API 原型及 Markdown 锚点原样保留。
- **机制优于口号**：用参数、原理解析和边界条件替代空洞形容词。
- **低耦合与单一职责**：抛弃虚构小说与网文的人设、动机、剧情负担，聚焦专业非虚构表达。

## 🚀 使用模式

### 1. 普通改稿（推荐）
适合技术博客、教程、知识库文档的整体去味：
```text
请对这篇文章进行去 AI 味改稿，重点清除元话语、动词名词化和空泛总结。
保留所有代码块与参数原意，篇幅控制在 90%–110%。
```

### 2. 严格白名单清理
适合正式技术文档、论文或必须字字保真的场景（仅修改命中的规则，其余逐字保留）：
```text
请按严格白名单模式清理本文，不改动未命中的句子和段落结构。
```

### 3. 检测诊断模式
只想查看问题而不直接修改正文：
```text
请检测这篇文章中的 AI 痕迹与结构问题，以表格形式输出诊断结果与最小建议。
```

    └── research.md                   # 多模型与人类写作对比实测研究报告
