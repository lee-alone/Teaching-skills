# 教案编写助手

## 这个技能解决什么问题

模型大多"会写教案"，但写出来的东西经常有四个毛病：

| 毛病 | 表现 |
| --- | --- |
| 结构散乱 | 板块顺序随意，该有的没有，不该有的堆一堆 |
| 目标空泛 | "理解……的意义""培养学生的……能力"，无法观测、无法检验 |
| 过程与目标脱节 | 目标写了三条，教学过程一条也没落实；活动很热闹，但和目标没关系 |
| 缺少可落地细节 | 只写"引导学生思考"，没写问什么、学生可能怎么答、答错了怎么办 |

根因是：模型不缺"教案有哪些板块"的常识，缺的是**优秀教案背后的思考顺序**——
先定什么、再推什么、最后验什么。顺序错了，板块填得再满也是散的。

**本技能的做法：不写"请按优质教案标准来写"这种空话，而是把思考顺序固化成流程，
每一步都产出可检查的东西，并在最后用一张对照表把目标、活动、评价三者锁死。**

## 什么时候用，什么时候不用

| 场景 | 用哪个 |
| --- | --- |
| 写教案、教学设计、备课构思（初高中任何学科） | **本技能** |
| 判断一份教案好不好、指出问题并改写、自检闭环 | **本技能**（运行 `check_plan.py`） |
| 理科符号与公式书写规范（LaTeX、化学方程式、物理正体单位与矢量等） | `science-lesson-prep`（理科符号规范技能） |
| 要 Word (.docx)／PPT (.pptx) 文件，且含理科公式或函数图象 | 先用本技能定教学设计 Markdown，再交给 `science-lesson-prep` 渲染 |
| 单纯问"某道题怎么解" | 都不用（直接回答） |

两个技能的分工：**本技能管"教什么、怎么教、怎么知道教会了"（教学设计与教案内容），`science-lesson-prep` 管"理科符号怎么规范书写、怎么原生不乱码渲染成 Word/PPT 文件"（符号规范与文档排版）。**

## 执行流程

### 第 0 步：确认基本信息

先确认这六项，缺哪项就问，用户说"你定"或信息实在拿不到时才按合理假设补，并在教案开头标注"（待确认）"：

学科｜学段年级｜教材版本与册次｜课题｜课时（第几课时／共几课时）｜课型

课型决定后续走哪套结构：新授课（概念／定理／规律）、复习课、阅读课、实验探究课、
习题课、单元整体教学。不同课型的差异见 `references/lesson-types.md`。

### 第 1 步：定位课标要求与核心素养落点

查 `references/curriculum-standards.md` 找到本学科的素养条目，回答两个问题：

1. 这节课对应课标的哪条内容要求？
2. 这节课最能在哪 **1–2 个**素养条目上使上劲？（不要五个全写上，写全等于没写）

**必须落到"这一节课"上**，不能写成"通过本节课培养学生的科学思维"这种放之四海皆准的话。

### 第 2 步：写三维目标

按 `references/objective-writing.md` 的公式写。三条硬要求：

1. **可观测**——用能看见学生做什么的动词（写出、画出、算出、说出、比较、判断、设计、论证……），
   不用"了解、理解、掌握、体会"这类看不见的动词单独作谓语。
2. **可测量**——带条件或标准（"能……至少 3 个例子""在 2 分钟内……""正确率不低于……"）。
3. **可对应**——每条目标编号（T1、T2、T3…），后面第 5 步的对照表要按编号挂上去。

三维按「知识技能／过程方法／情感态度·素养」分写。若本地区要求按核心素养分写，
按素养条目分写，但编号与可观测要求不变。

### 第 3 步：由目标倒推重难点与突破策略

**不要凭感觉写重难点，要从目标倒推**：

- **重点** = 目标里占时间最多、最核心的那一条所对应的知识或方法。
- **难点** = 学生达成目标时最可能卡住的地方。写难点必须写清三件事：
  ①卡在哪（具体的思维障碍）②为什么会卡（前概念／经验干扰／抽象度太高）
  ③用什么办法突破（具体的手段，不是"多加练习"）。

只写"难点：理解函数的概念"是不合格的；要写到"学生习惯用'一个 x 对应一个 y'的
算术思维，难以接受'对应关系'本身是研究对象，故用……"这个粒度。

### 第 4 步：构建教学思路（核心灵魂板块）

**一节优秀的初高中课必须有清晰的教学思路，绝非零散教学环节的随意拼盘。**
中学的认知深度决定了：在进入具体环节微观撰写之前，**必须构建独立的【教学思路】板块**，确立全课的顶层逻辑框架。

必须写明三项内容：

1. **整体教学构想（核心理念）**：
   一句话阐明本课的核心设计灵魂：基于什么真实情境，依托什么思维主线，经历怎样的认知跃升，达成哪些核心素养。
2. **教学主线架构图（核心问题链／任务链）**：
   用结构图（ASCII 架构树）呈现递进逻辑：
   - 1 个核心主问题（上位统领，具有探究张力）
   - 3–4 个层层递进的子问题（标注驱动的思维动作及目标指向 T1/T2/T3）
   - 每个子问题明确写出"预期学生回答"与"追问/引导方向"
3. **难点攻坚路线图（认知障碍破除路径）**：
   明确勾勒："学生前概念/思维卡点 ──► 认知冲突/实验/探究支架 ──► 思维转折突破 ──► 新认知建构与通法提炼"。

> **【双模式交互指引】**：
> - **模式 A（思路共创／启发备课）**：若用户提出"帮我想想这节课怎么设计""给我几条教学思路"或需求尚不明确，技能优先输出高密度的**【教学思路与主线架构】**，与教师对齐研讨；教师认可后再展开全案。
> - **模式 B（完整规范教案）**：若用户要求直接出教案，本板块作为核心独立板块完整置于教学过程之前，作为整节课的顶层逻辑统领。

### 第 5 步：逐环节写教学过程，填满四件事

每个环节都用这个格式（格式固定，自检脚本依赖它）：

```
### 环节一：情境导入（5 分钟）
- **教师活动**：……
- **学生活动**：……
- **设计意图**：……（这一环节对应哪条目标、突破哪个难点、承接教学思路中的哪一步）
- **评价点**：……（对应目标 T1：学生能……）
```

**四件事缺一不可**。只写"教师活动"是讲稿，不是教案；
只写"学生活动"没有教师动作，是活动方案，不是教案；
没有"评价点"就无法闭环，这是最常被漏掉、也最值钱的一项。

各环节用时之和 = 本节课时长度 −（3～5 分钟机动留白）。国内标准课时通常为 40 或 45 分钟（部分小学为 35 分钟，部分高中为 50 分钟），支持在课题信息中注明（如 `| 课时 | 1课时（40分钟） |`）或通过脚本传参。各环节标题必须注明用时，如 `### 环节一：情境导入（5分钟）`。

**内容质量与微观可操作性硬要求（拒绝形式主义）**：
- **【教师活动】写出具体发问**：必须包含核心主干提问与追问话术（用问号句或引语呈现），绝不能写成"教师引导学生思考"这类无发问动作的空话。
- **【学生活动】写出实质探究**：必须包含推导、计算、操作、辨析、同桌互查等主动思维动作，严禁通篇只写"认真听讲、做好笔记"等纯被动听讲词汇；且必须包含预期的**学生生成性回答**或**典型卡点/错误预设**。
- **【评价点】写出可观测证据**：写明看什么、查什么、什么算达标（如"能说出……的算达标，同桌互查正确率达 80%"），拒绝抽象的"评价学生课堂表现"。

### 第 6 步：闭环自检（必做，不可跳过）

两件事一起做：

**（1）填「目标—活动—评价」三栏对照表**，放在教学过程之后：

| 目标编号 | 教学目标 | 落实环节 | 达标证据（学生表现） | 评价方式 |
| --- | --- | --- | --- | --- |
| T1 | …… | 环节二、环节三 | 学生能独立写出…… | 板演＋同桌互查 |
| T2 | …… | 环节四 | 小组汇报中能说出…… | 口头点评 |

填表时**任何一格填不出来，就说明设计有漏洞**，回去补，不许留空。
这张表是整套流程的收口，也是最能一眼看出"目标与过程是否脱节"的地方。

**（2）跑自检脚本**：

```bash
python <skill>/scripts/check_plan.py 教案.md [--period 35/40/45/50] [--strict]
```

`check_plan.py` 只用 Python 标准库，无需安装任何第三方依赖。
脚本不仅检查 12 大板块结构、课时核算与闭环对照表，更集成了**教学法内容深度质检**：
自动扫描学情前概念、难点突破支架真实性、师生活动篇幅比与被动听讲拦截、教师发问细节等。退出码 0 才算过。
脚本报错必须改到 0；若存在 WARN 提示建议，逐条对照优化后再交付。
**脚本只查结构与形式，内容好不好仍要人工判断**——再对照
`references/quality-checklist.md` 逐条过一遍，不达标就改，改完再输出。

## 编写原则

1. **倒推而非顺写。** 顺序永远是"课标 → 目标 → 重难点 → 教学思路（主线架构） → 活动 → 评价"。
   从活动写起的教案，最后一定和目标对不上。
2. **对齐范例，而不是自由发挥。** 写之前先读 `assets/examples/` 里同学段或
   相近课型的范例，在**颗粒度**上对齐：范例写到多细，就写到多细。
   范例里的 `【设计说明】` 块解释了"这里为什么这样设计"，读它比读结论有用。
3. **具体压过漂亮。** 宁可写"学生可能答成'y 随 x 变大而变大'，需追问：
   如果 x 从 1 变到 2，y 一定变大吗？"——也不要写"引导学生深入理解函数关系"。
4. **教师语言，不用商业词。** 全文用教师日常说法：引导学生、通过活动让学生、
   学生动手操作、同桌互查、当堂反馈。**禁止**出现"亮点、价值、赋能、成果、
   抓手、打造、闭环"等词（"闭环"在本技能内部指目标—过程—评价三者一致，
   写进教案时要说"目标、过程、评价三者一致"）。
5. **公式写 LaTeX，不写 Unicode。** 行内 `$x^2$`、独立成行 `$$...$$`；
   不写 `x²`、`H₂O`（中文字体缺字形会变方框），也不手写 OMML。
   需要出 Word／PPT 时交给 `science-lesson-prep`。
6. **不编造课标原文与教材页码。** 记不准的课标表述就写成"课标要求学生能……"
   这种概括说法，不要加引号假装原文；教材页码不确定就不写页码。

## 输出格式

默认输出 Markdown，板块顺序：

```
课题信息 → 教材分析 → 学情分析 → 教学目标 → 教学重点与难点 →
教学思路（核心理念 + 主线架构图 + 难点攻坚路径）→
教学准备 → 教学过程（分环节落实四要素）→ 目标—活动—评价对照表 →
板书设计 → 作业设计（分层）→ 教学反思（留空待课后填写）
```

> **【Markdown 标题层级硬契约】**：
> - 所有 12 大必填板块必须使用**二级标题 `## `**（如 `## 课题信息`、`## 教学过程`）；
> - 【教学过程】中的具体教学环节必须使用**三级标题 `### `**（如 `### 环节一：情境导入（5分钟）`）；
> - 严禁使用一级标题 `#` 表示大板块（一级标题 `#` 仅允许作为文首教案总课题名称）。

用户指定 Word 时，写完 Markdown 后交给 `science-lesson-prep` 渲染；
若该技能不可用，直接把 Markdown 存成 `.md` 交付并说明。

## 硬性要求

1. **板块层级统一**：12 大板块必须使用二级标题 `## `，各教学环节必须使用三级标题 `### `。
2. 教学目标**必须编号**（T1、T2、T3…），且每条都能在对照表里找到落点。
3. **必须包含独立的【教学思路】板块**，清晰呈现整体构想、问题链/任务链架构图与难点攻坚路径。
4. 每个教学环节**必须**同时有"教师活动、学生活动、设计意图、评价点"四项。
5. **拒绝形式主义与空心教案**：
   - 【学情分析】必须指出学生已有基础、本课具体**前概念/迷思/认知卡点**，禁用"基础良好/思维活跃"等万能套话；
   - 【教学难点】必须写清卡点成因与**具体的教学法突破支架**（对比实验/反例/具象模型/问题阶梯），严禁写"加强练习/教师多讲"；
   - 【教学过程】教师活动必须有**具体发问话术**，学生活动必须有主动思维动作与**生成性/错误预设**，生本活动文本量应保持充实。
6. 对照表**不允许留空**，填不出来就回去改设计。
7. 各环节用时之和 = 课时长度 −（3～5 分钟机动）。国内标准课时通常为 40 或 45 分钟（部分小学 35 分钟，部分高中 50 分钟）。
8. 板书设计要呈现**知识的结构**（箭头、层级、对比关系），不是把标题抄一遍。
9. 作业分层（基础／提升／拓展），且**每层作业要能指回某条目标**。
10. 输出前跑 `check_plan.py`，退出码非 0 必须改到 0。
